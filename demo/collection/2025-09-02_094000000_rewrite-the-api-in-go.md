## Decision

Do not rewrite the order API in Go; keep the existing TypeScript service and fix the hot paths.

## Why

Profiling showed the latency came from three unindexed queries, not from the runtime. A rewrite would freeze features for a quarter to solve a problem an index solves in a day.

## Consequences

- Latency work targets queries and caching first.
- Revisit only if CPU-bound work appears that the runtime cannot handle.
